# Двусвязный список

Проект посвящён написанию собственного двусвязного списка с графическим выводом через Graphviz

## Возможности

| Функция | Описание |
| :--- | :--- |
Добавление элементов | Поддерживается вставка новых узлов в начало, в конец, а также до или после любого указанного элемента
Удаление элементов | Реализовано корректное извлечение узлов с автоматическим переназначением указателей соседних элементов
Поиск и доступ | Программа позволяет быстро находить элементы по значению или индексу и изменять их содержимое
Генерация графического дампа | Программа формирует актуальную схему состояния списка в виде изображения (например, PNG или SVG) в любой момент работы
Отображение связей | На схеме наглядно показаны прямые (next) и обратные (prev) указатели между узлами, а также специальные указатели на начало (head) и конец (tail) списка
Подсветка ошибок | Программа визуально выделяет цветом некорректные или разорванные связи, зацикливания и утечки узлов при возникновении сбоев

Все команды выполняются из папки проекта: `make` ищет `Makefile` только в текущей папке.

```bash
cd путь/к/проекту
make
```

После сборки в папке появляются программа list.

Цели `make`:

| Команда | Что делает |
| :--- | :--- |
| `make` | собирает программу |
| `make run` | запускает программу |
| `make clean` | удаляет .png .dot list_dumps.txt и папки bin_programs, obj, dot_of_dumps, png_dumps|

Пересборка идёт только для изменённых файлов, правка заголовка пересобирает все файлы, которые его подключают. Если изменил структуру в `.h` и поведение странное, выполни `make clean && make`.

### `list.h / .c`

Doubly Linked List on Arrays: реализация кольцевого двусвязного списка на параллельных массивах с поддержкой итераторов, верификацией целостности и генерацией HTML/Graphviz дампов.

<details>
<summary>Подробнее про list</summary>

**Doubly Linked List on Arrays**: реализация кольцевого двусвязного списка на трёх параллельных массивах с поддержкой итераторов за O(1), автоматической верификацией целостности и визуализацией через Graphviz. <details> <summary>Подробнее про список</summary>

#### Устройство структуры `list_t`

Список хранит элементы в трёх массивах фиксированной ёмкости `capacity`: `data`, `next` и `prev`. Ячейка с индексом `0` является фиктивной (header) и замыкает занятые элементы в кольцо.

* **Занятые ячейки:** `next[0]` указывает на первый элемент (`head`), а `prev[0]` — на последний (`tail`). В пустом списке `next[0] == prev[0] == 0`.
* **Свободные ячейки:** объединены в односвязный список через массив `next`, а индекс первой свободной ячейки хранится в `free_addr`. У свободной ячейки `prev[i] == -1`, а в `data[i]` лежит `LIST_POISON`.
* **Итераторы:** структура `list_iter_t` оборачивает физический индекс `idx` в массиве. При вставке и удалении элементов физические индексы остальных узлов не меняются, поэтому итераторы остаются валидными.

#### Таблица функций API

| Категория | Функция / Макрос | Сложность | Описание |
| :--- | :--- | :---: | :--- |
| **Жизненный цикл** | `LIST_CTOR(l, cap)` / `list_ctor` | O(N) | Выделяет массивы на `cap` ячеек (`cap >= 2`), инициализирует фиктивную ячейку `0` и собирает цепочку свободных индексов. |
| **Жизненный цикл** | `list_dtor(list)` | O(1) | Освобождает память массивов `data`, `next`, `prev` и обнуляет поля структуры. |
| **Итераторы** | `list_begin` / `list_end` | O(1) | Возвращают итератор на первый элемент (`next[0]`) и фиктивный конец (`0`). |
| **Итераторы** | `list_next` / `list_prev` | O(1) | Переходят к следующему или предыдущему элементу по массивам `next` и `prev`. |
| **Итераторы** | `list_get` / `list_iter_eq` | O(1) | Возвращают значение `data[it.idx]` или сравнивают два итератора по индексу. |
| **Модификация** | `list_insert_after` / `list_insert_before` | O(1) | Берут свободный индекс из `free_addr` и встраивают новый элемент после или перед итератором `it`. |
| **Модификация** | `list_push_front` / `list_push_back` | O(1) | Вставляют элемент в начало (после `end`) или в конец (перед `end`) кольца. |
| **Модификация** | `list_erase` | O(1) | Исключают элемент из кольца, записывают `LIST_POISON` и возвращают ячейку в `free_addr`. |
| **По индексу** | `list_nth` | O(N) | Линейным обходом от `begin` находит итератор элемента по его логическому номеру `that` (нумерация с `1`). |
| **По индексу** | `list_elem_push` / `list_elem_pop` | O(N) | Вставляют или удаляют элемент по логическому номеру через предварительный вызов `list_nth`. |
| **Диагностика** | `list_verify` | O(N) | Проверяет симметрию связей `prev[next[i]] == i`, длину кольца `size` и целостность свободной цепочки. |
| **Диагностика** | `list_dump` / `list_dump_html` | O(N) | Выводят текстовую таблицу массивов в поток `out` или записывают карточку ошибки в `log.html`. |
| **Визуализация** | `list_dump_graph` / `list_dump_graph_both` | O(N) | Генерируют `.dot` и `.png` схемы состояния списка через Graphviz в режимах `GV_ARCS` и `GV_ORTHO`. |

#### Коды возврата (`list_err_t`)

Ошибки делятся на предупреждения (`< 100`) и критические повреждения структуры (`>= 100`). При включённом `LIST_DEBUG` критическая ошибка автоматически вызывает `list_dump_html`, открывает `log.html` в браузере и завершает программу.

| Идентификатор | Код | Уровень | Описание |
| :--- | :---: | :---: | :--- |
| `LIST_OK` | `0` | OK | Операция выполнена успешно. |
| `LIST_NULL_PTR` | `1` | Warning | В функцию передан нулевой указатель `NULL`. |
| `LIST_BAD_CAPACITY` | `2` | Warning | Передана ёмкость `initial_capacity < 2`. |
| `LIST_ADD_TO_FULL_LIST` | `3` | Warning | Попытка вставки при `free_addr == 0` (список заполнен). |
| `LIST_BAD_INDEX` | `4` | Warning | Логический индекс `that` вышел за допустимые пределы. |
| `LIST_UNDERFLOW` | `5` | Warning | Попытка удалить элемент из пустого списка (`prev[0] == 0`). |
| `LIST_POP_UNKNOWN_ELEM` | `6` | Warning | Элемент с указанным логическим номером не найден. |
| `LIST_IO_ERROR` | `7` | Warning | Ошибка открытия файла `.dot` или `log.html`. |
| `LIST_DATA_OUT_OF_MEMORY` | `8` | Warning | Не удалось выделить память под массив `data`. |
| `LIST_NEXT_OUT_OF_MEMORY` | `9` | Warning | Не удалось выделить память под массив `next`. |
| `LIST_PREV_OUT_OF_MEMORY` | `10` | Warning | Не удалось выделить память под массив `prev`. |
| `LIST_CORRYPTED` | `101` | Error | Нулевые указатели на массивы, `capacity < 2` или `size` вне диапазона `[0, capacity)`. |
| `LIST_NEXT_BROKEN` | `102` | Error | Индекс `next` вышел за границы массива или нарушено условие `prev[next[i]] == i`. |
| `LIST_SIZE_MISMATCH` | `103` | Error | Количество элементов в кольце не совпадает с `size` или обнаружен цикл мимо ячейки `0`. |
| `LIST_FREE_CHAIN_BROKEN` | `104` | Error | Повреждён список свободных ячеек или их число не равно `capacity - size - 1`. |

#### Макросы конфигурации и визуализации

| Макрос / Тип | Значение | Назначение |
| :--- | :--- | :--- |
| `list_elem_t` | `double` | Тип хранимых значений в массиве `data`. |

| Функция | Что делает |
| :--- | :--- |
| `bytecode_read(const char* path, int* size)` | Читает бинарный файл с байт-кодом целиком, проверяет заголовок и каждую команду, возвращает массив ячеек (`code_t*`), размер записывает в `size`. |
| `bytecode_write(const char* path, const code_t* code, const int size)` | Записывает байт-код в бинарный файл: сначала заголовок, затем ячейки. |

Формат файла:

```text
[ magic ][ version_major ][ version_minor ][ count ][ ячейка 0 ][ ячейка 1 ] ...
  4 байта   2 байта          2 байта         4 байта    8 байт      8 байт
```
Структура BytecodeHeader - хранит весь заголовок файла - magic, version_major, version_minor и count)

| Поле | Назначение |
| :--- | :--- |
| `magic` | Сигнатура файла, байты `VMBC`. По ней отличают байт-код от чужого файла |
| `version_major` | Меняется при несовместимых изменениях формата, сейчас 2 |
| version_minor | Меняется при совместимых дополнениях, сейчас 0 |
| `count` | Количество ячеек `code_t` после заголовка. Размер файла должен точно совпадать с ним |

### `asm_main.c`

Содержит функцию `assembler()`: перевод программы с языка ассемблера в байт-код. Метки разрешаются за два прохода по файлу.

<details>
<summary>Подробнее про ассемблер</summary>

#### Макросы

| Макрос | Назначение |
| :--- | :--- |
| `MAX_LABELS` | Максимальное число меток в программе (128) |
| `LABEL_LEN` | Максимальная длина имени метки вместе с завершающим нулём (32) |

#### Структуры

| Структура | Описание |
| :--- | :--- |
| `Label` | Одна метка: имя (`name`) и адрес (`addr`), номер ячейки байт-кода |
| `LabelTable` | Таблица меток: массив `items` и текущее количество `labels_count` |

#### Функции

| Функция | Что делает |
| :--- | :--- |
| `label_find(const LabelTable* t, const char* name)` | Возвращает адрес метки или `-1`, если метки нет. |
| `label_add(LabelTable* t, const char* name, int addr)` | Добавляет метку. Возвращает `false`, если таблица заполнена, имя слишком длинное или метка уже есть. |
| `label_name_ok(const char* name)` | Проверяет имя: первый символ буква или `_`, дальше буквы, цифры и `_`, имя не совпадает с командой или регистром. |
| `main(int argc, char* argv[])` | Вызывает последовательно assembler() - основная часть программы и далее bytecode_write() для записи обработанного байт-кода. |
| `assembler(const char* path, int* size)` | Осуществляет перевод программы с языка ассемблера в байт-код |

<details>
<summary>Подробное описание работы assembler()</summary>

##### Синтаксис входного языка.
| Форма | Пример | Что получится до перевода в бинарный режим |
| :--- | :--- | :--- |
| команда без аргументов | `ADD` | `2` |
| число (в том числе дробное) | `PUSH 5` | `289 <биты числа 5.0>` |
| регистр | `PUSH AX` | `65 0` |
| ячейка памяти по номеру | `PUSH [4]` | `161 4` |
| ячейка памяти по регистру | `POP [AX]` | `199 0` |
| метка(определение) | `loop:` | ячейка не создаётся |
| метка(использование) | `JMP loop` | 40 <адрес> | |

#### Общая схема работы
```text
            input.txt
                |
                |
                V
      первый проход(pass = 1)
    (считает ячейки, ищет метки)
                |
                |      написание таблицы меток
                |--------------------->|
                |                      |
                V                      |LabelsTable
      второй проход(pass = 2)          |
  (пишет код, подставляет адреса)      |
                |                      |
                |<---------------------|
                |      чтение таблицы меток
                |
                V
        bytecode_write()
     (при отсутствии ошибок)
```

#### Разбор функции assembler()

`assembler()` возвращает указатель на начало массива с ячейками `code_t`, принимает имя `path` файла, который мы читаем и `int* size` - указатель на размер байт-кода, который мы прочитаем из файла.

```code
code_t* assembler(const char* path, int* size)
```
| Имя | Значение |
| :--- | :--- |
| `in` | читаемый файл с именем `path` |
| `capacity` | первоначальный размер байт-кода |
| `bytecode` | массив указателей на ячейки `code_t` байт-кода |
| `labels` | таблица меток, изначально пустая |
| `count` | количество команд и аргументов в `bytecode` |
| `pass` | номер прохода ассемблера

```code
FILE* in = fopen(path, "r");
    if (in == NULL)
    {
        perror(path);
        return NULL;
    }

    int capacity = 64;                                                    // первоначальный размер байт-кода
    code_t* bytecode = malloc(capacity * sizeof(code_t));
    if (bytecode == NULL)
    {
        fclose(in);
        fprintf(stderr, "bytecode out of memory in file %s\n", path);
        return NULL;
    }

    LabelTable labels = { .labels_count = 0 };
    int count         = 0;                      // количество команд и аргументов в bytecode
```

В цикле `for` реализуются 2 прохода по входному файлу `in`.

| имя | значение |
| `lineno` | номер текущей строки в файле |
| `line[]` | текущая строка |

В цикле `while`, который на каждом новом шагу читает новую строку входящего файла `in`, первым делом производится изменение строки:
Обрезка комментариев:
```code
char* comment = strchr(line, ';');
if (comment != NULL) *comment = '\0';                    //обрезка комментариев
```
| имя | значение |
| `used` | в `sscanf()` через `%n` ей присваивается количество прочитанных символов |
| `word` | первое слово в строке `line` |
Пропуск пустых строк или строк-комментариев:
```code
int used = 0;
char word[64] = "POISON";

if (sscanf(line, "%63s%n", word, &used) != 1) continue;  // пропускаем пустые строки
```
Далее определяем есть ли в конце `word` двоеточие и если да, то далее происходит следующая обработка метки:
Проверка валидности имени метки:
```code
word[strlen(word) - 1] = '\0';

if (!(label_name_ok(word)))
{
    fprintf(stderr, "%s:%d: bad label name '%s'\n", path, lineno, word);
    free(bytecode);
    fclose(in);
    return NULL;
}
```
Если метки еще не существует и проход первый, то происходит запись метки в массив меток:
```code
if (pass == 1 && !(label_add(&labels, word, count)))
{
    fprintf(stderr, "%s:%d: duplicate or too long label '%s'\n", path, lineno, word);
    free(bytecode);
    fclose(in);
    return NULL;
}
```
Далее происходит проверка на мусор после метки, `end_of_label` - указатель на конец метки, далее пропускаются пробелы и если указатель указывает не на `\0` или `\n`, происходит запись ошибки:
```code
char* end_of_label = line + used;
while (isspace((unsigned char)*end_of_label)) end_of_label++;
if (*end_of_label  != '\0' && *end_of_label != '\n')
{
    fprintf(stderr, "%s:%d: unexpected '%s' after label\n", path, lineno, end_of_label);
    free(bytecode);
    fclose(in);
    return NULL;
}
```

Если же слово в строке не было меткой, значит это была команда и теперь произодится обработка команды:
`op` - опкод команды
```code
int op = find_command(word);
if (op == -1)
{
    fprintf(stderr, "%s:%d: unknown command '%s'\n", path, lineno, word);
    free(bytecode);
    fclose(in);
    return NULL;
}
```
Далее идет проверка, что в `bytecode` еще влезает команда с аргументами и его расширение, если нет:
```code
if (count + 3 > capacity)
{
    code_t* bytecode_tmp = realloc(bytecode, 2 * capacity * sizeof(code_t));
    if (bytecode_tmp == NULL)
    {
        free(bytecode);
        fclose(in);
        fprintf(stderr, "bytecode out of memory in file %s\n", path);
        return NULL;
    }
    capacity *= 2;
    bytecode = bytecode_tmp;
}
```
Теперь `flags` - флаги команды `op`, а `operand` - ее возможный аргумент, сейчас еще не заполнены.
```code
int flags   = 0;
code_t operand = 0;
```
Далее если из isa определяется принимает ли команда аргументы и если да происходит обработка аргументов:
```code
char  arg_text[64];
int   arg_used     = 0;

if (sscanf(line + used, "%63s %n", arg_text, &arg_used) != 1)
{
    fprintf(stderr, "%s:%d: missing argument for %s\n", path, lineno, word);
    free(bytecode);
    fclose(in);
    return NULL;
}
```
